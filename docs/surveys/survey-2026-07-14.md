## 1. Refactoring

### High impact

- **ML knowledge leaks into the ML-agnostic engine (Layer 3 violation).**
  `src/core/engine.ts:157-183` computes `paramCount` and hand-formats a
  `paramBreakdown` string (`"conv2d: 576 + bias: 64 = 640"`) and assumes the first
  output is `outputShape`. CLAUDE.md and [ADR-0003](../adr/0003-six-layer-ml-agnostic-architecture.md)
  state Layers 1–4 know nothing about ML. This was flagged on 2026-07-05 and is still
  present. Fix: move subgraph metadata formatting to a Layer-5 domain presenter (e.g.
  a `metadataFormatter` capability on `NodeDefinition`), leaving the engine to route
  raw outputs only. Related: `src/core/ports.ts:38,44` and `engine.ts:130,152`
  hard-check `node.type === 'subgraph.input'/'subgraph.output'` — replace with
  capability flags.

- **Pixel-array → `<canvas>` loop still duplicated ~12–15 times.** The
  `createImageData` grayscale/RGB loop is hand-rolled in `EngineNode.tsx:261`,
  `step-through/transformations/shared.tsx`, `MseLossViz.tsx:96`, the `backprop/*`
  and `dashboard/samples` views, and `inspector/LayerDetail.tsx`. `src/ui/PixelCanvas.tsx`
  already exists as the canonical component but is under-adopted. This is item #1 in
  CLAUDE.md's "Reuse before duplicating" list. Consolidate onto `PixelCanvas` (and a
  shared `heatColor`, which has 3–4 divergent copies returning CSS strings vs `[R,G,B]`).

- **Number formatter (`fmt`/`signed`, scientific notation, `—` for null) copy-pasted.**
  Distinct variants with different magnitude thresholds live in
  `step-through/transformations/MseLossViz.tsx:113`, `Conv2dViz.tsx:613`,
  `PoolViz.tsx:324`, `NormViz.tsx:141`, plus two separate `format.ts` files
  (`src/ui/backprop/format.ts`, `src/ui/step-through/transformations/format.ts`).
  Merge into one shared util and pick a consistent threshold convention.

### Medium impact

- **Backend node-discovery pattern repeated.** `backend/visualize/backprop_sim.py:789`
  defines `_find_key_nodes()` (data/loss/prediction), but
  `backend/engine/graph_builder/inference.py:58-71` re-walks the same graph inline.
  Promote to a shared helper. (CLAUDE.md "Reuse before duplicating" item.)

- **Prediction extraction (softmax → argmax → probs) re-implemented.**
  `backend/engine/graph_builder/stats.py` has canonical `prediction_from_logits`, but
  `backprop_sim.py` re-derives it inline (~lines 281, 966). Reuse the helper.

## 2. Organization

Large files worth splitting (line counts verified):

| File | Lines | Problem |
|------|------:|---------|
| `src/ui/useGraph.ts` | 1326 | God-hook: mutations, serialization, undo/redo, subgraph nav, saved blocks, copy/paste, backend comms, viz pinning. Untested bridge across all layers. |
| `src/ui/inspector/LayerDetail.tsx` | 1084 | 7 independent viz modes (Heatmap, LossLandscape, Dream, ConfusionMatrix, Misclass, LatentGrid). Extract a `detail-views/` subdir. |
| `backend/dataprep/data_loaders.py` | 987 | ML-agnostic Protocols + 10 concrete dataset loaders + shared tokenize/vocab utils all mixed. Extract Protocols and a `text_utils.py`; consider a `DATASET_LOADERS` registry mirroring the training-plugin pattern. |
| `backend/training/base.py` | 677 | `TrainingContext`/`Result` + optimizer/scheduler builders + validation/accuracy/snapshot helpers. Kitchen-sink used by all paradigms. |
| `backend/visualize/layers/misc.py` | 409 | Dumping ground: 8 unrelated viz functions (MHA, SDPA, concat, add, reparameterize, reshape, embedding, RNN). Split by family (attention, concat, structural). |

Other structural notes:
- The `backend/api/` split into thin per-concern routers is **good** — don't merge it.
  One caveat: `backend/api/training.py` and `visualize.py` reach directly into many
  `visualize/*` submodules; a single public dispatch surface in `visualize/__init__.py`
  would tighten the boundary.
- `src/ui/useGraph.ts` split is the top organizational lever because it also unblocks
  testing the core graph/serialization paths (see §3).

## 3. Testing

### Critical gaps

- **`backend/generate/` has zero tests.** Confirmed: no `test_generate*.py`.
  `text_generate.py` (autoregressive loop, tokenizer-mode detection, decode/sampling)
  and `gan_generate.py` (noise routing, generator forward) are user-facing and complex.
  Highest-risk untested backend code.

- **Backend visualization is thinly covered.** `tests/backend/test_node_viz.py` has 14
  test functions covering a subset of the ~30 forward/backward viz functions in
  `backend/visualize/layers/*`. Backprop sim, loss landscape, activation max, denoise,
  latent viz are essentially untested at the unit level.

- **API handlers barely exercised.** `tests/backend/test_api.py` checks route-registration
  count and `/health` only. The `generate`, `visualize`, `models`, and `library` route
  handlers have no behavioral tests.

- **Persistence untested.** `backend/persistence/runs_store.py` (run save/load) has no
  `test_persistence.py`.

### Medium gaps

- **Frontend core Layer 2/4 untested.** `src/core/ports.ts` (`getNodePorts`,
  `getSubgraphPorts`) and `src/core/datatypes.ts` (`DataTypeRegistry`) have no direct
  tests. Serialization round-trip for nested subgraphs (in `useGraph.ts`) is untested —
  a round-trip bug silently corrupts undo/redo, copy/paste, and agent persistence.
  Promoting pure helpers out of `useGraph.ts` (see §2) makes these testable without React.
- **Export tests are string-only.** `test_export.py` asserts generated code *contains*
  substrings but never executes it. Running the generated script (subprocess/compile)
  would catch real breakage — especially relevant given the custom-dataset export gap (§4).
- **Training paradigms:** only detection logic is tested (`test_training.py`); no
  per-paradigm loop smoke test (standard/GAN/diffusion/autoregressive).

## 4. Unfinished Work

- **Custom-dataset export is a stub (HIGH).** `backend/export/datasets.py:314` returns
  `"# TODO: Add dataset loading for {dtype}\ntrain_loader = None"`. Issue #7 landed
  custom datasets for training (backend + frontend) but **not** export — a graph with a
  `data.custom` node exports to a script with a no-op loader. `backend/dataprep/custom_dataset.py`
  already contains the loading logic to mirror. Also extend `_bpe_dataset_code()`
  (`datasets.py:99-290`) to cover `data.custom` + BPE.

- **Dead model endpoints (MEDIUM).** `backend/api/models.py:16-53` defines
  `POST /save-model`, `POST /load-model`, `GET /saved-models` — no frontend references
  them (grep returns nothing). The frontend uses `/download-model`, `/upload-model`,
  `/download-weights`, `/upload-weights` (lines 83+). Remove the three dead routes.

This was the only unfinished-feature TODO of substance; the rest of the codebase is clean
of stray stubs/`NotImplementedError`.

## 6. Next Steps (highest leverage)

Beyond the fixes already itemized, the biggest forward-looking levers:

1. **Make export runnable end-to-end** — finish custom-dataset export (§4) *and* upgrade
   `test_export.py` to execute generated scripts. Export is a headline educational feature
   and currently can silently emit broken code.
2. **Unblock core testing by promoting pure helpers out of `useGraph.ts`** —
   `serializeGraphData`/`deserializeGraphData`, `friendlyError`, `organizeGraph` into
   `src/core/`, then test them. Pairs with the §2 god-hook split.
3. **Restore the Layer-3 invariant** — move param/metadata formatting and `subgraph.*`
   type checks behind `NodeDefinition` capabilities.
4. **Shared canvas/format primitives** — one `PixelCanvas` + one `heatColor` + one
   number formatter, so the next visualization is drop-in rather than copy-paste.
