# NodeTorch Frontend Survey — 2026-07-05

Read-only survey scoped to the **frontend** (`src/`, ~21.2k LOC across 136 files).
Six dimensions (refactoring, organization, testing, unfinished work,
documentation, next steps), fanned out to parallel agents and synthesized here.

**Resolved since the 2026-06-21 whole-repo survey** (verified against current code,
not re-reported below):
- **Backend URL centralization** — `src/api/base.ts` provides `apiUrl()`/`wsUrl()`
  (respecting `VITE_API_BASE`); the 35 hardcoded `localhost:8000` literals are gone
  (~49 call sites now use the helpers).
- **`TrainingDashboard.tsx` split** into `src/ui/dashboard/{types,charts,panels,samples}.tsx`.
- **Epoch type unified** — `EpochData` replaced the duplicate `EpochRecord`.
- **`SerializedGraph` validation on load** — `useGraph.ts:591` now validates + surfaces friendly errors.
- **`runShape` dirty-tracking** — verified *already correct*: caching is on in shape
  mode and all ~11 `runShape` call sites mark dirty first. (Prior survey's concern does not hold.)

**Headline:** the 6-layer architecture is intact and the recent refactors landed.
Remaining frontend debt is concentrated in four places, each surfaced by multiple
dimensions:

1. **`src/ui/useGraph.ts` (1481 lines) is a god-hook** — flagged by refactoring,
   organization, testing, *and* next-steps. It is also the single largest untested surface.
2. **Canvas/viz primitives are duplicated** — `heatColor` (2–3×), `Heatmap` (3–4×),
   `displayToken` (2–3×), and raw `getContext('2d')` pixel rendering across ~16 files.
3. **Backward step-through is a wired-up but discarded no-op** — the UI shows "coming soon"
   while still POSTing an expensive backprop sim each time.
4. **ML knowledge leaks into Layers 1–4** — violating the core design invariant.

## 1. Refactoring

### High impact
- **Leaky layering — ML metadata formatting inside Layer 3.** `src/core/engine.ts:161–177`
  computes `paramCount` and hand-formats `paramBreakdown` (e.g. `"conv2d: 576 + bias: 64"`)
  and assumes `outputShape` is the first output — all ML-specific, in the ML-agnostic engine.
  Move to a `NodeDefinition` capability / Layer-5 presenter.
- **Leaky layering — subgraph sentinel string checks in core.** `src/core/ports.ts:38,44`
  and `src/core/engine.ts:130,152` compare `node.type === 'subgraph.input'/'subgraph.output'`.
  Layers 1–3 should not know specific node types; add capability flags on `NodeDefinition`
  (e.g. `isSubgraphInput`) queried by the engine.
- **Hardcoded node-type sets in Layer 2 validation.** `src/core/validation.ts:64–75`
  (`LOSS_TYPES`/`OPTIMIZER_TYPES`/`DATA_TYPES`) plus inline literals (e.g. `:83` `=== 'ml.loss.gan'`).
  Adding a loss/optimizer/dataset requires editing core validation. Query registry
  capabilities/`category` instead.
- **Conv/pool output-shape formula `floor((D+2P−K)/S)+1` hand-written 6×:**
  `conv2d.ts:79`, `conv1d.ts:70`, `maxpool2d.ts:51`, `avgpool2d.ts:30`, `maxpool1d.ts:22`,
  `conv-transpose2d.ts:31` (ceil variant). Extract `convOutputSize(...)` into `src/domain/shape-math.ts`.
- **`useGraph.ts` fetch→catch→json→status boilerplate repeated ~12×** (`runInfer`, `runTest`,
  `runExport`, weights, etc.), with `'Cannot connect to backend'` duplicated ~21× across
  `useGraph.ts`, `StepThroughPanel.tsx`, and the inspector detail panels. Wrap in one
  `callBackend(endpoint, data)` helper (belongs next to `src/api/base.ts`).

### Medium
- **`displayToken()` duplicated** — `StepThroughPanel.tsx:554` vs `AttentionViz.tsx:176`
  (behaviorally diverging: JSON-stringify fallback in one). Move to `step-through/token-utils.ts`.
- **`validation.ts` has no JSDoc** (see §5) — the only core file violating the CLAUDE.md mandate.

## 2. Organization

- **Split `src/ui/useGraph.ts` (1481 lines)** — ≥9 concerns in one hook. Suggested carve-out:
  - `friendlyError` (`:74–98`, pure PyTorch-error copy) and `organizeGraph` (`:1217–1296`, pure
    longest-path layout) → move to **Layer 1** (`src/core/`, testable, no React).
  - Backend comms (`:670–1192`, ~520 lines, 12 fetch calls) → a `useGraphBackend` hook + the
    `callBackend` helper above.
  - Undo/redo + batching (`:147–378`), subgraph navigation (`:199–342`), serialization/saved-blocks
    (`:567–668`), copy/paste (`:1298+`) → separate hooks.
- **Promote a shared `src/ui/canvas/` module.** The right primitives already exist in
  `src/ui/step-through/transformations/shared.tsx` (`FeatureMapsGrid`, `GrayscaleCanvas`,
  `VectorBars`, `Histogram`, `HeatmapCanvas`) but are buried 3 levels deep, so consumers reimplement.
  Concretely: **`heatColor` defined 3×** with different return types — `LayerDetail.tsx:512` (CSS
  string, schemes), `AttentionViz.tsx:701` (`[R,G,B]`), `charts.tsx:604` (CSS); **`Heatmap`/heatmap
  components 3–4×** (`LayerDetail.tsx:466`, `shared.tsx:268`, `charts.tsx:622` `GradientHeatmap`,
  `AttentionViz.tsx:216`); raw pixel rendering hand-rolled in ~16 files. Unify into
  `src/ui/canvas/` with one `heatColor(t, scheme)` and one `<HeatmapCanvas>`.
- **Split `src/ui/inspector/LayerDetail.tsx` (1084 lines)** — 7–8 independent viz modes
  (`Heatmap:466`, `LossLandscapeView:579`, `DreamCanvas:721`, `ConfusionMatrixView:774`,
  `MisclassCard:905`, `LatentGridView:964`) → `inspector/detail-views/`, canvas widgets → the shared module.
- **Split `src/ui/step-through/StepThroughPanel.tsx` (811 lines)** — `GenerateView:563`,
  `DenoiseView:705`, sample-preview components → sibling files; resolve the `displayToken` dup.
- Not worth splitting further: `charts.tsx` (824), `PropertyInspector.tsx` (502),
  `AttentionViz.tsx` (716), step-through `types.ts` (428) are cohesive and well-sectioned.

## 3. Testing

Current: **7 files / 136 tests**, all deterministic (no brittle frontend tests). Well-covered:
`core/graph.ts`, `core/validation.ts`, shape executors, `chat/graphTools.ts`, structural
serialization round-trips. **Untested & load-bearing: `useGraph.ts` (0 tests) and
`core/engine.ts` (0 tests)** — a testing-pyramid inversion (solid base, hollow bridge).

Highest-risk gaps (all still open from the prior survey):
1. **Serialize/deserialize round-trip incl. nested subgraphs** (`useGraph.ts:569/591`) — the
   persistence + undo + agent-bridge + backend-payload format. Single most load-bearing untested code.
2. **Undo/redo + batching** (`useGraph.ts:147–173`) — one-undo-per-batch, nested `beginBatch`
   no-op, 50-entry cap, redo-clear-on-mutation. Off-by-one silently corrupts history.
3. **WS training-message handler** (`useGraph.ts:~1092` `ws.onmessage`) — ~15 fields unpacked with
   no schema validation; `graphTools.test.ts` already assumes the `trainingProgress` shape nothing
   produces under test. Mock-WS `epoch×N → done` test.
4. **`core/engine.ts` execution + subgraph recursion** (`:97–186`) — topo order, dirty-skip caching,
   multi-output port routing, sentinel injection, subgraph param aggregation.
5. **`isValidConnection`** (`useGraph.ts:375`) — 4 rules (self, port existence, type compat,
   single-input dedup); only indirectly exercised via the agent tool.
6. **`friendlyError` table test** (`useGraph.ts:74–95`) — ~10 regexes over user-facing educational
   copy; a PyTorch version bump silently degrades it.

**Testability blocker:** the load-bearing helpers (`friendlyError`, `toRFNodes/Edges`,
`organizeGraph`, `pruneInvalidEdges`) aren't exported. Moving the pure ones to `core/` (see §2)
makes them unit-testable and closes the biggest gaps at once.

  (`:404–406`). Result discarded every time the mode is switched. Either finish the view or gate off
  the pipeline + hide the tab.

- **Dead export** `fallbackInsight` (`step-through/insights.ts:20`) — implemented, never imported.
- **Minor:** `Conv2dViz.tsx:420` `onClick={() => {}}` (intentional in transpose mode — harmless);
  `useGraph.ts:378` `console.log('[nodetorch] Connection rejected …')` is an intentional dev aid.

## 5. Documentation

- **`src/core/validation.ts` has zero JSDoc** — violates CLAUDE.md ("JSDoc on all core interfaces
  and functions"). Missing on `ValidationError` (`:15`), `validateForward` (`:22`),
  `validateTraining` (`:77`). Every other core file complies. ~10-minute fix.
- **Whole frontend subsystems have no design doc** — `src/ui/chat/` (agent UI: ChatRail,
  useAgentChat, graphTools, AgentSettings), `src/ui/sidebar/`, `src/ui/dashboard/`. CLAUDE.md
  "Key files" omits `chat/` and `sidebar/`. The agent is the largest undocumented subsystem
  (recommend `docs/agent.md`).
- **README omits agent setup** — the assistant needs an API key and `requirements.txt` pulls
  `openai`/`anthropic`, but README/`start.sh` never mention how to enable it.
- **`docs/frontend-architecture.md` is accurate** — spot-checked line citations
  (`graph.ts:12/57`, `engine.ts:97`, `nodedef.ts:85/113`, `domain/index.ts:41`) all still match.
  Good. (Backend docs — `docs/backend-architecture.md`, `CONTRIBUTING.md` — remain stale post-split,
  but that's out of this frontend scope; see the prior survey.)

## 6. Next Steps (highest leverage)

- **Surface validation errors on the offending node** (High, ~2h, educational). `ValidationError`
  already carries `nodeId` (`validation.ts:16`) and `EngineNode.tsx:119` already renders
  `metadata.error`; today training-validation errors only appear as toolbar text. Badge each on its
  node. Pure UI wiring over existing data, squarely on-mission.
- **Unified backend-offline UX** (High, ~2h). "Cannot connect to backend" is handled ad-hoc in ~15+
  places with no single indicator; a student who forgot to start the backend sees scattered nothing.
  One shared offline banner (pairs naturally with the `callBackend` helper from §1).
- **Resolve backward step-through** (High). Finish the visualization or disable the pipeline; stop
  paying backend compute for a discarded result.
- **Close the serialize/deserialize + engine test gaps** (High) — see §3; the highest data-loss risk.
